# Movie Review Factory

Windows-local AI movie review/recap pipeline. Claude Code CLI (`claude`) can generate research, outline, script, and multi-shot scene-selection reasoning; deterministic local tooling handles timestamps, media processing, state, and verification.

Pipeline: ingest → research → transcript/scene index → outline → script → scene plan → TTS → alignment → render → QA → metadata → thumbnail → publish.

MVP target: Vietnamese 8–12 minute 16:9 review/recap. The local dashboard previews three generated thumbnail candidates and lets the operator choose the primary image. Media Explorer indexes source scenes, silent spans, dialogue, persisted AGY visual observations, true multilingual embeddings, and anonymous cross-scene person tracks. Scene and Library Search can rank semantically similar results by cosine similarity even when the query shares no literal words with the stored text; Library Search also supports person/action/location/object/project/type filters, duration/confidence bounds, and saved searches. Person continuity starts with anonymous labels such as `Person 1`; the operator may assign a manual alias, but the system never infers a real-world identity. Continuity v2 keeps appearance/clothing history, ambiguity flags, mean confidence, and recency-weighted continuity confidence. The explorer seeks to cited timecodes, exports WebVTT, and offers heuristic highlights with optional 9:16 clips. Suggestions and transcript chat require review against source footage. Publishing is not automatic.

## One-file local web

Run `node scripts\build-onefile.mjs` to generate `movie-review-factory.js`. On 64-bit Windows, double-click that single file. First run bootstraps a private runtime under `%LOCALAPPDATA%\MovieReviewFactory`: Node LTS when Node is absent, managed Python 3.12 through portable `uv`, FFmpeg/FFprobe when absent, and the required Python app/Whisper/semantic-search/TTS packages. It then starts an ephemeral localhost port and opens the default browser. Jobs live in a `jobs` folder beside the JS file (falling back to LocalAppData when that folder is not writable), so replacing the JS with a newer build does not erase jobs.

A fresh machine only needs Windows Script Host + PowerShell (standard on supported Windows) and Internet access for first-run downloads. Node/Python/FFmpeg and the installed `faster-whisper`/`fastembed`/`edge-tts` packages are cached afterward, so subsequent launches do not reinstall them. Downloaded Node, `uv`, and FFmpeg archives are SHA256-verified against upstream metadata. Claude Code remains optional: `content_agent=scaffold` works without it. Edge-TTS still needs network access when synthesizing speech. Faster-whisper stores its model under `%LOCALAPPDATA%\\MovieReviewFactory\\models\\whisper`; semantic search stores its multilingual model under `%LOCALAPPDATA%\\MovieReviewFactory\\models\\embeddings`. Both caches have been verified for offline reuse on Windows.

In the compact dashboard, expand **Tạo project mới**, choose an MP4 and create a project. The workspace uses Khám phá, Biên tập, Duyệt & xuất, and Tệp tabs; the top status card keeps the next action, progress, and QA-gated MP4 download within reach. The file is streamed into that project's folder with upload progress; a local source path is also available under the advanced option. As soon as import finishes, the project is queued for background indexing so Media Explorer and search become ready without blocking, while you keep working on other projects; the dashboard shows live index progress and Run/Stop/Delete cooperatively pre-empt it. Run to create the draft script, review and approve it, then run again to synthesize narration, render, verify, and download `final.mp4` from the top status card or Duyệt & xuất tab once QA passes. The TTS pass records spoken-word boundaries for subtitles (at most two short lines per cue), and the rendered chapter cuts use measured voice section bounds when available. Review/approve metadata, then press **Đóng gói bàn giao** in Duyệt & xuất to download a ZIP with MP4, SRT/VTT, thumbnail, title/description/tags, actual-render chapters, upload notes and SHA-256 revision details. This is a manual upload package; inspect source use and any QA advisories before posting. After `scene_plan.json` exists, Timeline & Continuity exposes card-based preview, lock/unlock, source trim, shot replacement, within-section reorder, B-roll suggestions/automatic duplicate replacement, and section-level visual regeneration. Scene cards expose Find similar using the stored scene vector as the query. TTS needs network access. Project and artifact lists use cards. To remove several old projects, tick their cards or Choose all, press Delete selected, and type `XOA N` with the displayed count. Single-project Delete still requires typing its exact ID. A running/importing project cannot be deleted; deleting a project removes its owned files but leaves an externally referenced source file untouched.

### Creator workflow additions

The new project form records the review thesis, tone, audience, spoiler policy and claims to avoid. After AGY drafts the script, select a saved narration span to label it as recap with an internal scene/transcript reference or as original opinion. The tag invalidates script approval until reviewed again. In the editor, create named versions before changes and restore script, timeline, captions, metadata or a compatible passing final. Optional music and sound effects require a rights note and source file; narration remains the master track, music ducks beneath speech, and changing an audio setting reruns render and QA. The export area can make a 9:16 short only from the finished approved review, with its own MP4 and captions. The QA panel reports decoded frame/silence intervals and measured loudness/peaks for creator review.

For long scripts, Edge TTS is requested in short chunks and joined with measured word timing; it still requires network access. A TTS error does not replace the previous passing MP4. A new CTA or edit is export-ready only after a fresh render, QA and handoff package. The [creator production roadmap](docs/plan/creator-production-roadmap.md) tracks the real-video and clean-machine checks needed before release.

If `DASHBOARD_TOKEN` is set, open the local URL with `#token=<your-token>` in its fragment. The page shell loads without a token, but job data requires the bearer token; after an authenticated API response, video uses a same-site, HttpOnly cookie scoped to the media stream. Keep this service bound to localhost.

Useful checks:

```powershell
node movie-review-factory.js --self-test --no-browser
node movie-review-factory.js --self-test --no-browser --no-network
node movie-review-factory.js --no-browser
```

## Developer setup

Requires Python 3.11+ and FFmpeg/FFprobe.

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -e ".[media,semantic,tts]"
mrf init-job .\jobs\demo --movie-title "The Matrix (1999)" --content-agent claude
mrf validate-job .\jobs\demo
mrf run .\jobs\demo --until script
mrf approve-script .\jobs\demo --confirm
mrf run .\jobs\demo --until thumbnail
mrf validate-scenes .\jobs\demo --truth .\jobs\demo\scene_truth.json
```

`validate-scenes` compares the deterministic lexical/visual scorer with the semantic+identity scorer without rendering. The optional truth JSON contains one `expected_scene_indexes` array per script section and reports top-1/candidate hit rates, repeat count, adjacent-scene count, and mean top score.

`scripts/release_gate.py` is the clean-machine release gate: fixture → ingest → transcript → scenes → search → content → tts → alignment → render → qa → export with a 13-step checklist (`--offline` for a no-network run). Latest development-machine acceptance on 2026-09-27: rebuilt one-file SHA-256 `94c603028d9f5012bd25ddb98d8b9900f622e22b5c8ce2caa90e4b9c2208c7fb`, 461 tests passed / 6 skipped, WSH plus online/offline one-file self-tests passed, online release gate reached 18/18 PASS, and offline reached 12 PASS / 6 expected network BOO / 0 FAIL. This Windows installation already has Node, Python and FFmpeg, so those results do not claim a clean-machine first bootstrap. `scripts/bench_ann.py` measures linear-scan versus exact-numpy search latency to drive the ANN decision.

Whisper transcribes in the detected source language, independently of the review's output language. On CPU it uses int8, up to 8 estimated physical cores (half the logical threads), and batch size 4; the one-file launcher selects batch size 8 when installed RAM is at least 16 GB. Set `MRF_WHISPER_CPU_THREADS` and `MRF_WHISPER_BATCH_SIZE` (1–16) to tune throughput versus RAM use. Larger models need more compute and are not automatically faster. For low-resolution sources, optionally set `MRF_RENDER_MAX_HEIGHT=540` before starting the server to cap the output canvas at 960×540 instead of upscaling to 1920×1080; output resolution and encode time decrease together.

`mrf index <job>` runs source-only indexing (ingest → transcript → scene index, plus AGY visual/story/embedding scene-memory in the claude/agy modes) without any content stage — the same work the web app performs in a background FIFO queue after each import. Import returns immediately and the project is auto-enqueued (one job indexes at a time so other projects stay usable, with live per-stage progress in the dashboard); set `MRF_AUTO_INDEX=0` to opt out and trigger indexing manually via `mrf index`, the project's index action, or `POST /jobs/{id}/index`. Running or deleting a project cooperatively stops its pending index first, and a later `run` reuses the cached index.

`--content-agent scaffold` is the offline/default mode. `--content-agent claude` invokes `claude -p` with JSON-schema structured output for research, outline, script, and scene selection while keeping the script approval gate intact. Optional runtime overrides: `MRF_CLAUDE_BIN`, `MRF_CLAUDE_MODEL`, `MRF_CLAUDE_EFFORT`, `MRF_CLAUDE_TIMEOUT_SECONDS`, and `MRF_CLAUDE_RETRIES`. Claude retries one timeout by default; non-timeout CLI/auth/schema failures still fail immediately. Claude runs in restricted/plan mode with an empty MCP config; research exposes only WebSearch/WebFetch, while outline/script/scene-plan expose no tools. `--content-agent agy` sends those same research, outline, script, and scene-plan stages to the local Aki AGY pool instead of Claude Code, and transcript chat follows the job's content-agent mode; the dashboard lists the choice as the `AGY pool` option. Each request tries the four pool roles in order (`advisor`, `executor`, `experiment`, `reviewer`) and moves to the next role when a worker is busy, out of quota, or returns unusable output. Optional overrides: `MRF_AGY_MODEL` (default `gemini-3.7-flash-medium`), `MRF_AGY_EFFORT` (`low`, `medium`, `high`; default `medium`), `MRF_AGY_TIMEOUT_SECONDS` (default `130`), `MRF_AGY_RETRIES` (attempts per role, 0-3; default `1`), `MRF_AGY_COOLDOWN_SECONDS` (default `300`), and `MRF_AGY_PROMPT_MAX` (default `26000`). Pool scheduling goes through `pool_scheduler.py`, which skips a cooled-down role, resumes partially used requests, and writes per-role quota/health telemetry (`status`, `latency_ms`, `cooldown_until`) to `%LOCALAPPDATA%\MovieReviewFactory\runtime\pool_health.json`. It requires a configured, running AGY pool; without Claude Code or the pool, `scaffold` remains the offline default. When the local Aki AGY pool is configured and running, scene planning inspects every bounded indexed scene, stores grounded visible descriptions/tags/actions, and runs a second continuity pass that assigns recurring visible people anonymous labels such as `Person 1`. It never guesses a real-world name or celebrity identity. FastEmbed (`sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`, 384 dimensions) embeds transcript, visual, and anonymous-person context locally; bounded scene retrieval merges cosine-ranked semantic hits with lexical/timeline evidence. Vision starts with `advisor`; on quota exhaustion it tries `executor`, `experiment`, then `reviewer`, skipping depleted accounts for the rest of the job. Frames temporarily inherit the pool workspace's permissions and are removed after inspection. Cached observations/tracks remain usable if a later AGY pass is unavailable; `scene_plan.json` records visual, identity, and semantic modes/errors. Each signed-in AGY account consumes its own quota.

See PLAN.md, docs/AGENT_WORKFLOW.md, and docs/REFERENCES.md.

Only process source footage you are authorized to use. The system is for original commentary/review, not re-uploading full copyrighted films.

Cancellation: while a project is running, the Vietnamese **Dừng project** control stops only that project (including its Claude process tree on Windows). Completed artifacts remain, cancelled stages are resumable with Run, and stale Running stages are recovered after restart.
